# אתר מעקב תרגילים

בונה אתר שממפה את תרגילי הקורס למטריצה של **נושא × יחידה**, עם התרגיל והפתרון
נפתחים בתוך הדף, סימון "נפתר", דגלים וסינון. ההתקדמות נשמרת בדפדפן.

התשתית כבר קיימת בתיקייה — `tools/build.js` מרכיב את `index.html` מתוך
`data/course.json` + `data/questions.json` + התמונות. **לא עורכים את
`index.html`**, הוא תוצר build ונדרס בכל הרצה. גם את `tools/template.html` לא
נוגעים אלא אם באמת צריך יכולת חדשה.

## שלב 1 — לברר מה יש ביד

**זה השלב החשוב ביותר. אל תתחילו לבנות לפני שהוא סגור.**

בדקו מה כבר יש בתיקייה (`ls`), ואז בקשו במפורש את מה שחסר. אל תנחשו ואל
תתחילו מ"בערך". הודעת הפתיחה צריכה להיות קצרה וקונקרטית — רשימה של מה
שצריך, לא הרצאה.

### חובה

| מה | למה | אם אין |
|---|---|---|
| **הסילבוס** | ממנו נגזרים היחידות, הנושאים והאשכולות. בלעדיו אין מבנה. | לבקש שתכתוב בחופשי: מה בחומר, איך הקורס מחולק (שבועות? פרקים?), וכמה יחידות |
| **התרגילים** | התוכן עצמו | אין אתר. לבקש. |
| **מה בחומר למבחן** | קורסים מוציאים נושאים. בלי זה האתר מציג חומר מיותר. | לשאול במפורש: "הכל בחומר, או שיש חלקים שירדו?" |

### אם קיים — שווה מאוד לבקש

- **פתרונות** — הם מה שהופך את האתר משימושי למרכזי
- **מבחני עבר ופתרונותיהם** — אם המטרה היא תרגול למבחן
- **דף נוסחאות**
- **שם הקורס, המוסד ומספר הקורס** — נכנסים לכותרת ולשורת העל

### מה להגיד לה על הצורה

- **תרגילים** — קובץ או צילום לכל שאלה זה הנוח ביותר. PDF של סט שלם גם עובד,
  פשוט נחתוך. שמות הקבצים לא משנים.
- **פתרונות** — הדרך המהירה היא להפנות את צילומי המסך של macOS ישירות
  לתיקייה ולצלם **לפי הסדר**:
  ```bash
  defaults write com.apple.screencapture location "$PWD/solutions" && killall SystemUIServer
  ```
  (לחזרה: `defaults delete com.apple.screencapture location && killall SystemUIServer`)
- **אם הפתרונות מגיעים כערימה כרונולוגית בלי תוויות** — שתגיד את זה. המיפוי
  ייעשה לפי התוכן, והסדר הכרונולוגי הוא שקובע מה עמוד 1 ומה עמוד 2 של אותה
  שאלה. זה עובד, אבל צריך לקרוא כל צילום.

## שלב 2 — לקרוא את הסילבוס ולגזור מבנה

קראו את הסילבוס במלואו לפני שמסווגים משהו.

**היחידות** (`weeks` ב-`questions.json`) — איך הקורס מחולק. אם זה לא שבועות,
שנו את `unit` ב-`course.json` ל-`פרק`/`פרקים` וכו׳.

**הנושאים והאשכולות** (`topics`, `bands` ב-`course.json`) — כאן נמצא השיקול
היחיד שבאמת קובע אם המטריצה שווה משהו:

> **נושא חייב לחזור ביותר מיחידה אחת.** אם כל נושא שייך ליחידה אחת בדיוק,
> המטריצה יוצאת אלכסון ריק — 80% מהתאים מקף — ואין בה שום מידע מעבר לרשימה.

אל תיקחו את כותרות השבועות ותהפכו אותן לנושאים. חפשו **מושגים רוחביים**
שחוזרים לאורך הקורס. בדקו את עצמכם: מפו את המילוי לפני שבונים, וראו שיש
לפחות שניים-שלושה נושאים שנוגעים ביותר מעמודה אחת. אם אין — הנושאים גסים מדי
או צמודים מדי ללוח הזמנים, ושווה לחשוב מחדש.

**אשכולות** — עד שישה, הקיבוץ העליון של הנושאים. 3–5 נושאים לאשכול זה טווח טוב.

**סימונים בסילבוס** — שימו לב לכוכביות, צבעים, הערות כמו "בוטל" או "פתרון
בהרצאה". הם נכנסים לנתונים (`star`, `void`, `lecture`) ומקבלים סינון ותגיות.

## שלב 3 — לוודא כיסוי לפני שמסווגים

הצליבו את רשימת השאלות מהסילבוס מול הקבצים שבתיקייה, **ודווחו לפני שממשיכים**:

- **שאלות בסילבוס שאין להן קובץ** → `missing`, ותג "חסר תרגיל"
- **קבצים שאין להם שאלה בסילבוס** → כנראה מחוץ לחומר. לשאול.
- **כפילויות**
- **שאלות שבוטלו** → `void:true`. **לא למחוק** — בלעדיהן המספור מדלג בלי
  הסבר. הן מוצגות מעומעמות, לא נספרות בהתקדמות, ואם יש להן פתרון עדיין
  אפשר לפתוח אותן.

דווחו את הפערים כרשימה קצרה ושאלו אם להשלים, לפני שמשקיעים בסיווג.

## שלב 4 — עיצוב: לבנות, להראות, לתת לבחור

**אל תשאלו "איזה צבע את רוצה". תבנו ותראו.**

בחרו 2–3 ערכות שמתאימות למקצוע (`tools/themes.json` מפרט לכל ערכה למה היא
מתאימה), ולכל אחת:

1. עדכנו `theme` ב-`course.json`
2. `node tools/build.js`
3. הריצו שרת מקומי וצלמו: `python3 -m http.server 8777`
4. שמרו את הצילום

הציגו את הצילומים יחד ותנו לה לבחור. ציינו בשורה אחת מה מייחד כל אחת (הצבע
והגרף), בלי להרצות.

אחרי הבחירה — בדקו גם מצב כהה ומסך צר לפני שממשיכים.

## שלב 5 — לסווג את השאלות

לכל שאלה ב-`data/questions.json`:

- `id` — המזהה כמו בסילבוס, בדרך כלל `<סט>-<שאלה>`. **מספר הסט אינו בהכרח
  מספר היחידה** — שאלה מסט 09 יכולה להופיע בסילבוס תחת שבוע 08. `week` הוא
  מה שקובע את העמודה.
- `topic` ראשי אחד, ו-`also` לנושאים משניים
- `title` — קצר, כמו בסילבוס
- `desc` — מה השאלה מבקשת, במשפט או שניים. זה מה שנכנס לחיפוש, אז שיהיה בו
  את המושגים.
- `level` 1–5, `parts` מספר הסעיפים, `star` / `void` / `lecture` לפי הסילבוס

קראו את התרגיל עצמו לפני שכותבים `desc`. תיאור שנגזר מהכותרת בלבד חסר ערך.

## שלב 6 — למקם את הקבצים

```
exercises/<id>.png              התרגיל
solutions/<id>.png              פתרון בעמוד יחיד
solutions/<id>-1.png, -2.png    פתרון בכמה עמודים, לפי הסדר
```

אם הפתרונות הגיעו כערימה כרונולוגית: קראו אותם בסדר, זהו איפה כל שאלה
מתחילה ונגמרת, וכל טווח רציף הוא שאלה אחת. `tools/rename.sh` נותן שמות לפי
סדר הצילום כשיודעים מראש את הרשימה.

ההצגה נגזרת מקיום הקובץ, לא מדגל בנתונים — קובץ שיתווסף יופיע מעצמו.

## שלב 7 — לבנות ולבדוק

```bash
node tools/build.js
python3 -m http.server 8777
```

ה-build נופל על נושא שלא קיים, אשכול שלא קיים, או מציין מקום שלא מולא,
ומזהיר על פתרון למזהה לא קיים או נושא בלי שאלות. **אל תתעלמו מאזהרה.**

בדפדפן, לפני שמכריזים שסיימתם:

- נפתחת מגירה, התרגיל והפתרון נטענים, אין תמונה שבורה
- פתרון מרובה עמודים מוצג **כבלוק אחד רציף** ולא כתיבה לכל עמוד
- הסינונים מסתכמים נכון (מסומנות + לא מסומנות = הכל)
- מצב כהה, ומסך צר (שם ברירת המחדל היא תצוגת רשימה)
- אם יש נוסחאות — שהן רונדרו ואין `.math-err`

## שלב 8 — לפרסם

```bash
./update.sh "תיאור השינוי"
```

לרפו חדש:
```bash
gh repo create <שם> --public --source=. --remote=origin --push
gh api -X POST repos/<user>/<שם>/pages -f "source[branch]=main" -f "source[path]=/"
```

ציינו שהרפו ציבורי ושהחומר הוא של סגל הקורס, אם זה המצב.

## מלכודות שכבר נפלנו בהן

**בידוד דו-כיווני.** ביטוי לטיני/מתמטי בתוך משפט עברי נשבר: `|11⟩+|00⟩` מוצג
כ-`⟨00|+⟨11|` — הקטים הופכים לברות, כלומר סימון **שגוי**, לא רק מכוער.
התבנית עוטפת רצפים כאלה ב-`<bdi>` אוטומטית (`bidi()`), אבל אם מוסיפים מקום
שמציג טקסט חופשי — להשתמש ב-`escb()` ולא ב-`esc()`.

**`$$` ב-`String.replace`.** במחרוזת ההחלפה `$$` הוא תו `$` בודד מוגן, ולכן
נוסחה בשורה נפרדת נמעכת לנוסחה בתוך שורה. `build.js` מזריק עם `split/join`
בדיוק בגלל זה — לא להחליף בחזרה ל-`replace` עם מחרוזת.

**שם קובץ פתרון מכיל מקף.** `06-2.png` הוא השאלה `06-2` בעמוד יחיד, לא שאלה
`06` עמוד `2`. ההכרעה ב-`build.js` היא מול רשימת המזהים המוכרים — לא לפצל על
המקף האחרון.

**`loading="lazy"` בתוך מיכל נגלל** נתקע ומשאיר את הפתרון ריק. התמונות
במגירה נטענות מיד בכוונה.

**ברירת המחדל במסך צר היא רשימה ולא טבלה.** מטריצה בטלפון דורשת גלילה
אופקית בכל שורה.

**מרחב שמות ב-localStorage.** `ns` ב-`course.json` חייב להיות ייחודי לכל
אתר, אחרת שני אתרים על אותו דומיין דורסים זה לזה את ההתקדמות.
